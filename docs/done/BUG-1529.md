# BUG-1529 — False highlighting error on close

**Item:** BUG-1529 — False highlighting error on close
**Branch:** `bugfix/bug-1529-highlight-null-document`
**Run:** vibe/2026-10-20-split-close-statusbar

## Summary

**Was it a bug?** Yes, a false alarm. "Syntax highlighting stopped: Value cannot be null. (Parameter
'document')" no longer appears when a pane, or a pane's last tab, is closed.

**Why it appeared:**

- A pane with no tab gives its (hidden) editor no document.
- AvaloniaEdit.TextMate 12.0.0 builds its model for whatever the editor's document is, `null`
  included. Its `DocumentSnapshot` then throws `ArgumentNullException` (`document`), and the
  installation hands the exception to the failure handler. The pane put it on the status line, where
  it stayed until another message replaced it.
- A closed pane's editor goes through that state on its way out, hence the message on every split
  close.
- Nothing was actually broken: the next document gets a model of its own, and colouring resumes.

**The fix:** `EditorAppearance` wraps the failure handler it hands to the installation. It drops this
one case: an `ArgumentNullException` whose `ParamName` is `document`, received on the UI thread while
the editor has no document. Everything else still goes to the status line. The check reads the editor
only on the UI thread, because the background tokenizer reports from its own thread.
