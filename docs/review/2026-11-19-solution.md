### TEST-01 — [High] A test fails at HEAD: the instance pipe stalls on a client that sends more than the server reads

**Locations**
- `tests/Enigma.TextEditor.Core.UnitTests/Instances/InstanceServerTests.cs:87-104`
- `src/Enigma.TextEditor.Core/Instances/InstanceServer.cs:100`
- `src/Enigma.TextEditor.Core/Instances/InstanceServer.cs:158-165`
- `src/Enigma.TextEditor.Core/Instances/InstanceProtocol.cs:87-93`

**Why it matters** — `dotnet test` is red on `main` right after the 1.20.0 release, so every later dev starts from a failing baseline and a real regression in the hand-over of files between launches would hide behind it. Verified: 4 failures out of 4 runs, each lasting exactly `DefaultRequestTimeout` (5 s). Inferred, not verified (the review is read-only): the pipe is created without buffer sizes, the server reads only the 4-byte length of the stranger's 18-byte request and then writes its refusal while the client is still inside its own write, so each side waits for the other to read until the server's deadline drops the connection. The one-byte read at line 165 is also satisfied by any leftover byte rather than by the peer closing, so "held open until the other end has read the answer" does not hold for a peer that sent more than was read.

**Recommended fix** — create the server pipe with explicit buffer sizes (the `NamedPipeServerStream` constructor that takes `inBufferSize` and `outBufferSize`) so a short write completes without the peer reading, and replace the single one-byte read after the reply by a drain loop that reads until the peer closes or the deadline passes; then rerun the class on Windows and Linux. If it still fails, the inference above is wrong and the test needs instrumenting before anything else.

**Rule** — review-standards `reference/tests.md` §Isolation and determinism; `reference/exceptions.md` §Async and cancellation.

**Why it matters** — `File.WriteAllBytesAsync` truncates the target before it writes: a full disk, a dropped network share or a crash in the middle leaves the user's file empty or cut short, with the previous content gone. ### PERF-01 — [Medium] The autosave copies and rewrites every unsaved buffer, every five seconds

**Locations**
- `src/Enigma.TextEditor.Desktop/Services/SessionAutosave.cs:132-140`
- `src/Enigma.TextEditor.Desktop/ViewModels/WorkspaceViewModel.cs:1002-1009`
- `src/Enigma.TextEditor.Desktop/ViewModels/DocumentViewModel.cs:359`
- `src/Enigma.TextEditor.Core/Sessions/SessionFile.cs:57-62`

**Why it matters** — each tick captures the session on the UI thread, which takes `Document.Text` of every dirty document (up to 32 MB each), and whenever the capture differs from the last one — a caret move is enough, the caret offset is part of each tab — the whole state, all unsaved text included, is serialised and flushed to disk. With one large unsaved file open this is a multi-megabyte copy on the UI thread and a multi-megabyte synchronous disk flush every five seconds while the user types or navigates.

**Recommended fix** — keep each document's unsaved text in its own side file next to `session.json`, rewritten only when that document's `ITextSourceVersion` has changed since its last write, so `session.json` holds layout, carets and references and stays small; capture the text only for documents whose version changed.

**Rule** — review-standards `reference/performance.md` §I/O and data access, §Allocations and strings.

## In good shape

- Exception handling is deliberate: all 64 catch clauses name the types they handle, most through a `when` filter, and none is empty or swallows silently — `src/Enigma.TextEditor.Core/Files/FileOperations.cs`.
- Nothing is fired and forgotten unobserved: every un-awaited task goes through one helper that reports to the three global handlers — `src/Enigma.TextEditor.Desktop/Extensions/TaskExtensions.cs`, `src/Enigma.TextEditor.Desktop/Services/UnhandledExceptionHooks.cs`.
